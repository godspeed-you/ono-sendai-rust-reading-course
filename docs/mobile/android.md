# Android

> **Mobile packages are consumers of the normal generated course artifact. They do not define a
> separate course implementation.** The Gradle project in `mobile/android/` wraps the exact `dist/`
> that `make build` produces (copied to `app/src/main/assets/public/`, disposable, verified by hash
> manifest); nothing in it renders, rewrites or duplicates course content.

This guide covers the Android side: local Linux setup, builds, emulators and the installed-app test
suite, signing, and the native behaviour decisions. Shared concepts (layout, content equivalence,
persistence schema, plugins) are in [`mobile/README.md`](../../mobile/README.md); Google Play in
[`docs/store/google-play.md`](../store/google-play.md).

## Local setup (Linux)

Only needed for Android builds; the course, the static tests and the browser tests need none of it.

1. **JDK 21** (Temurin): e.g. extract `OpenJDK21U-jdk_x64_linux_hotspot_*.tar.gz` to `~/jdk/`.
2. **Android command-line tools**: download *Command line tools only* from
   developer.android.com/studio, unpack to `~/Android/Sdk/cmdline-tools/latest/`.
3. Environment (put it in a file and source it, e.g. `~/Android/env.sh`):

   ```bash
   export JAVA_HOME=$HOME/jdk/jdk-21.0.12.1+1
   export ANDROID_HOME=$HOME/Android/Sdk
   export ANDROID_SDK_ROOT=$ANDROID_HOME
   export PATH=$JAVA_HOME/bin:$ANDROID_HOME/cmdline-tools/latest/bin:$ANDROID_HOME/platform-tools:$ANDROID_HOME/emulator:$PATH
   ```

4. SDK packages:

   ```bash
   sdkmanager --licenses
   sdkmanager "platform-tools" "platforms;android-36" "build-tools;36.0.0" "emulator" \
     "system-images;android-36;google_apis;x86_64" "system-images;android-24;google_apis;x86_64"
   ```

5. Node from `.nvmrc`, then `make mobile-setup` (installs the pinned Capacitor packages) and, for the
   emulator tests, `npm ci` in the repository root (Playwright).
6. Emulators need hardware virtualisation: `/dev/kvm` must exist and be accessible (`ls -l /dev/kvm`;
   add yourself to the `kvm` group if needed).

## Build

```bash
make mobile-sync       # make build + copy dist/ into the native projects + prove equality
make android           # debug APK      -> mobile/android/app/build/outputs/apk/debug/app-debug.apk
make android-release   # release APK    -> .../apk/release/app-release.apk   (release key or debug key)
make android-bundle    # release AAB    -> .../bundle/release/app-release.aab (for Google Play)
cd mobile/android && ./gradlew lint   # abortOnError; policy and the few documented suppressions: app/lint.xml
node mobile/tools/mobile.mjs verify-package mobile/android/app/build/outputs/bundle/release/app-release.aab
```

`make android*` always re-syncs first, so a stale web copy cannot be packaged. The first Gradle run
downloads Gradle and the Android Gradle Plugin (several minutes); later debug builds take about a
minute on a 4-core machine.

Built-package checks (no emulator): `ANDROID_HOME=… node --test tests/mobile/android.test.mjs` reads
the built APK with `aapt2 dump badging` (zero `uses-permission`, package, versions, SDK levels, label)
and, with `ONO_BUNDLETOOL=/path/to/bundletool-all-1.18.3.jar`, the AAB with `bundletool dump manifest`
and `bundletool validate`.

### Sizes (course 1.0.0)

Measured on 2026-09-30 (Linux, AGP 8.13, no minification; the web content is stored compressed):

| Artifact | Size |
|---|---|
| `dist/` (uncompressed, 117 files) | 10.5 MB (10 511 720 bytes) |
| static release ZIP / TAR.GZ | 1.62 MB / 1.55 MB |
| debug APK | 6.54 MB (6 538 604 bytes) |
| release APK | 4.66 MB (4 658 777 bytes) |
| release AAB | 4.56 MB (4 557 833 bytes) |
| Play download size estimate (`bundletool get-size total`, all device configurations) | 4.28-4.31 MB |
| installed on the API 36 emulator (release build, `/data/app/...`, incl. ART artefacts) | 11.7 MB code + about 1 MB data after first use |

About 3 MB of each package is the Capacitor/AndroidX runtime; the rest is the compressed course.
Cold start on the API 36 emulator (software rendering, 4 host cores): first frame (`am start -W`
TotalTime) 1.6-2.1 s, of which the launch screen is shown until the WebView draws; the course home is
fully loaded about 1.5 s after the WebView starts navigating (`PerformanceNavigationTiming.loadEventEnd`),
and the test harness observes the initialised course page about 5 s after `am start` including its own
DevTools-attach overhead. Physical devices with GPU rendering are considerably faster. The suite
records these numbers in `measurements.txt` on every run.

## Emulators and the installed-app test suite

### AVDs

```bash
echo no | avdmanager create avd -n ono-phone-36  -k "system-images;android-36;google_apis;x86_64" -d pixel_7
echo no | avdmanager create avd -n ono-tablet-36 -k "system-images;android-36;google_apis;x86_64" -d pixel_tablet
echo no | avdmanager create avd -n ono-phone-24  -k "system-images;android-24;google_apis;x86_64" -d pixel_7
# optional, faster on busy machines: hw.ramSize=3072 in ~/.android/avd/<name>.avd/config.ini
emulator -avd ono-phone-36 -no-window -no-audio -no-boot-anim -gpu swiftshader_indirect -no-snapshot &
```

The `google_apis` images include Chrome, which the external-link tests use as "the browser".

### Running the suite

```bash
make android                                   # the suite installs this debug APK
tests/mobile/android/run.sh                    # boots ono-phone-36 if no device is attached, whole suite
tests/mobile/android/run.sh --avd ono-tablet-36 -- tablet.spec.ts
tests/mobile/android/run.sh --avd ono-phone-24  -- minsdk.spec.ts
make mobile-test-android                       # the same suite against an already running device
```

`run.sh` waits for boot, disables animations, installs the APK, records logcat, runs Playwright and
leaves everything in `mobile/build/android-test/<avd>/` (git-ignored): `screenshots/`,
`logcat.txt`, `crash.txt`, `report/` (HTML), `junit.xml`, `measurements.txt` (cold-start times,
layout numbers, axe summaries), `device.txt`. With several devices attached set `ANDROID_SERIAL`.

How it works: the debug build is debuggable, so its WebView exposes a DevTools socket; Playwright's
Android support (`_android`, over adb) attaches to it and inspects the real page, while the tests
drive the device like a user with adb: real touch taps (`input tap` at the element's screen
position), `KEYCODE_BACK`, edge-swipe back gestures, the 3-button bar, Home, `am start -W`,
`am force-stop`, `am kill`, rotation, `wm size`/`wm density`, `font_scale`, `cmd uimode night`,
display-cutout overlays and airplane mode. Private app files are read with `run-as` (Preferences in
`shared_prefs/CapacitorStorage.xml`, WebView storage in `app_webview/`). Release builds are not
debuggable and expose nothing.

| Spec file | Covers |
|---|---|
| `launch.spec.ts` | cold launch of a fresh install straight into the course home (no login/network/onboarding screen), cold-start time, warm launch keeps page and scroll, process death in the background → home with *Continue where you left off*, About shows "Android app, version … (build …)" |
| `learning.spec.ts` | navigation by touch (home, lessons, pager, menu, learn-rust, glossary, About, chapters), every chapter and a lesson of each from the packaged copy, multiple choice, ordered hints, solution, notes typed via the IME path, completion, checklist, annotations and code tools |
| `persistence.spec.ts` | progress/notes/hints/checklist/last lesson across Home + force-stop, the native snapshot (schema v1), WebView storage wiped → restored from the snapshot, three kinds of corrupt snapshot ignored and replaced, reset clears both stores, upgrade with `adb install -r` |
| `back.spec.ts` | back key, gesture-navigation edge swipe and 3-button bar: menu closes first, history walks back page by page, at the home page the app goes to the background (same process, no crash); back cancels the reset confirmation |
| `layout.spec.ts` | 320/375/430 CSS px (via `wm size`/`wm density`), device default portrait/landscape with rotation keeping page, scroll, open hint and notes; no page-level horizontal scroll, code scrolls locally, code ≥ 12 px, primary touch targets ≥ 44 CSS px; tall display cutout in 0°/90°/270° (WebView never overlaps status bar, navigation bar or cutout); font scale 1.3 and 2.0; light/dark incl. switching at run time; axe-core (WCAG 2.1 A/AA, light and dark) on six pages; keyboard focus order, skip link, menu ARIA/inert, selectable text |
| `offline.spec.ts` | no permission in the installed package; a network probe from the page fails even while the device is online; the spec §59 flow in airplane mode with Wi-Fi and data off, including restart |
| `external.spec.ts` | an injected `https://` link (plain and `target=_blank`) opens Chrome via `ACTION_VIEW`, the WebView stays on the course page, back returns to the same page and state; a link nothing can open does not break the course |
| `minsdk.spec.ts` | API < 26 only: the smoke flow above on an old WebView (raw DevTools protocol instead of Playwright) |
| `tablet.spec.ts` | Pixel Tablet landscape (1280 CSS px) and portrait (800), 1024 and 768 CSS px, side-by-side navigation where wide enough, rotation keeping state (skipped on phones) |

Tests tagged `@smoke` are a quick subset (`-- --grep @smoke`) on current Android versions.

On slow emulators the system occasionally shows "System UI isn't responding" (an emulator hiccup
that steals key focus); the helpers answer it with *Wait* and log it in `measurements.txt`.

## Native behaviour

**Launch screen.** `AppTheme.NoActionBarLaunch` is an androidx core-splashscreen theme: navy
`#0b1f2a` (the course header colour) with the `>_` mark as a vector (`res/drawable/splash_mark.xml`).
`MainActivity` calls `installSplashScreen()`, so Android 7-11 show the same screen as the Android 12+
system splash. It disappears on the first frame; there is no keep-on-screen condition and no delay.

**Window, system bars, safe areas.** The app is edge to edge (Capacitor `SystemBars` with
`insetsHandling: native`): the WebView is laid out inside the system-bar and display-cutout insets, so
course content can never sit under the status bar, navigation bar or a notch (verified with the tall
cutout overlay in three rotations). The window behind the bars uses the course page colour
(`#fbfaf7` light, `#11161c` dark, `values-night`). Status and navigation bar icons follow the system
theme, as the course does via `prefers-color-scheme`. Capacitor's SystemBars keeps the icon colour it
resolved at start-up, which made icons unreadable after switching the system theme while the app was
open; `MainActivity.onConfigurationChanged` re-applies it (the activity handles `uiMode` changes
itself so the learner's page is not reloaded).

**Back.** Implemented in the shared course (`assets/course.js`, App plugin `backButton`): close the
open course menu or reset confirmation; else go back in the course's history; else `minimizeApp()`
(the app goes to the background like any launcher activity; it is not finished, so returning is
instant). Works identically with the back key, the gesture and the 3-button bar, including predictive
back on Android 16 (targetSdk 36), because Capacitor's App plugin registers an AndroidX
`OnBackPressedCallback`. Capacitor's default without a listener would go back in WebView history and
then *do nothing* at the start of history, trapping the user.

**Lifecycle.** `launchMode=singleTask`; orientation, screen size, density, keyboard and `uiMode` (light/dark)
changes are handled in place (no reload, no lost scroll position). A font-size change recreates the
activity like in any app; the page reloads and all stored state is kept. After process death the
app starts at the course home, which offers *Continue where you left off* (resume pattern B).

**External links.** Capacitor hands every navigation to a non-local URL to the system as an
`ACTION_VIEW` intent (browser or chooser); the privileged WebView never loads it. If no app can handle
the URL, nothing happens and the course stays usable.

**Persistence.** WebView `localStorage` (`https://localhost` origin, stable across updates) plus the
Preferences snapshot `ono-rrc.snapshot` in `shared_prefs/CapacitorStorage.xml` — schema and rules in
[`mobile/README.md`](../../mobile/README.md#behaviour-of-the-installed-apps). An app update
(`adb install -r`) keeps both; uninstalling removes both; nothing is backed up to the cloud.

**Permissions and network.** The manifest requests nothing. AndroidX Core merges an app-private
signature permission (`…DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION`, for `ContextCompat.registerReceiver`
on Android 7-12) into every app; this app registers no receivers, so the overlay manifest
`app/src/nopermissions/AndroidManifest.xml` (used by both build types) removes it and the built APK/AAB
declares **no `uses-permission` at all**. Without `INTERNET` the OS denies the app every socket, so the
course is offline by construction: a `fetch()` from the page fails even on an online device.
`usesCleartextTraffic=false`.

## Minimum SDK

minSdk stays at **24**, Capacitor 8's minimum. Verified on the `system-images;android-24;google_apis;x86_64`
emulator with `minsdk.spec.ts`, locally with WebView/Chrome 69.0.3497.100 and in CI with the image's stock
WebView 53.0.2785.124: the app
installs and launches (cold start `TotalTime` about 1 s), the course home renders without page-level
horizontal scroll, course.js initialises, the Capacitor bridge is present, a lesson opens by touch,
hints unlock in order, the solution opens, notes and completion are stored, the native snapshot is
written, a restart shows *Continue where you left off* with the note restored, and system back closes
the menu, walks history and finally leaves the app.

Two platform facts behind that result:

* WebViews before Chromium 87 lack `DOCUMENT_START_SCRIPT`, so Capacitor injects its bridge as an
  inline `<script>` at the start of each HTML response. The course's CSP is a `<meta>` element, which
  only governs content *after* it, so the injected bridge still runs while every course page keeps
  `script-src 'self'` for its own content.
* On Android 7-9 the status bar is not drawn over the app (no edge to edge), so there is nothing to
  inset; the page starts below the status bar.

Android 7's WebView is updatable (Google Play), so real devices usually run a newer one than the
image. Playwright cannot attach to WebViews older than Chromium 74, so on API < 26 the suite runs only
`minsdk.spec.ts`, which uses plain DevTools `Runtime.evaluate` and adb input.

## Signing

Build types: `debug` (debug key, debuggable, WebView DevTools on) and `release` (not debuggable,
signed with the release/upload key from the environment, or with the debug key as a fallback).

| Variable | Meaning |
|---|---|
| `ONO_ANDROID_KEYSTORE` | path to the keystore (`.jks`/PKCS12), outside the repository |
| `ONO_ANDROID_KEYSTORE_PASSWORD` | keystore password |
| `ONO_ANDROID_KEY_ALIAS` | key alias |
| `ONO_ANDROID_KEY_PASSWORD` | key password (defaults to the keystore password) |
| `ONO_REQUIRE_RELEASE_SIGNING=1` | fail the configuration if no keystore is set (use it for every store build) |

Create the **upload key** once (keep it and its password in a password manager plus an offline
backup; never in the repository — `.gitignore` and `tests/mobile/config.test.mjs` refuse keystores):

```bash
keytool -genkeypair -v -keystore ~/keys/ono-rust-course-upload.jks -storetype PKCS12 \
  -alias upload -keyalg RSA -keysize 4096 -validity 10000 \
  -dname "CN=<owner name>, O=<owner>, C=<country>"
export ONO_ANDROID_KEYSTORE=~/keys/ono-rust-course-upload.jks ONO_ANDROID_KEY_ALIAS=upload
read -rs ONO_ANDROID_KEYSTORE_PASSWORD && export ONO_ANDROID_KEYSTORE_PASSWORD
ONO_REQUIRE_RELEASE_SIGNING=1 make android-bundle
"$ANDROID_HOME/build-tools/36.0.0/apksigner" verify --print-certs mobile/android/app/build/outputs/apk/release/app-release.apk
```

For CI releases store it as the repository secrets `ONO_ANDROID_KEYSTORE_BASE64`
(`base64 -w0 ~/keys/ono-rust-course-upload.jks`), `ONO_ANDROID_KEYSTORE_PASSWORD`,
`ONO_ANDROID_KEY_ALIAS` and optionally `ONO_ANDROID_KEY_PASSWORD`; only `release.yml` reads them.
Google Play holds the app signing key (Play App Signing); the owner only ever has the upload key,
which Google can reset if lost ([google-play.md](../store/google-play.md#signing-upload-key-and-play-app-signing)).

Verified on 2026-09-30 with a throwaway keystore created outside the repository: with the four
variables set, `assembleRelease bundleRelease` produced an APK that `apksigner verify --print-certs`
reports as signed (APK Signature Scheme v2) by `CN=Ono Rust Course TEST ONLY` and an AAB that
`jarsigner -verify` reports as signed by the same certificate (SHA-256
`6b:c0:c6:…:8b:b4`); without the variables the release APK carries `CN=Android Debug`; with
`ONO_REQUIRE_RELEASE_SIGNING=1` and no keystore Gradle stops at configuration time with
*"ONO_REQUIRE_RELEASE_SIGNING=1 but ONO_ANDROID_KEYSTORE is not set"*.

## CI

`.github/workflows/mobile-android.yml` (push to `main`/`mobile-v1`, pull requests touching `mobile/`,
`tests/mobile/`, `assets/`, `generator/`, `course/` or the workflow, manual runs; `contents: read`,
no secrets):

1. **build** (ubuntu-24.04): pinned Rust toolchain → `scripts/course build` → Node from `.nvmrc`,
   `npm ci` in `mobile/` → `mobile.mjs sync` → `MOBILE_REQUIRE_SYNC=1` static tests → JDK 21 →
   `assembleDebug lint bundleRelease assembleRelease` (debug key) → pinned bundletool (SHA-256
   checked) → built-package tests and `mobile.mjs verify-package` on APKs and AAB → sizes in the job
   summary → artifacts `android-packages`, `android-lint-report`.
2. **emulator** (matrix, KVM enabled, `reactivecircus/android-emulator-runner`): API 36 Pixel 7 (whole
   suite), API 36 Pixel Tablet (`tablet.spec.ts`), API 24 Pixel 7 (`minsdk.spec.ts`); artifacts
   `android-test-<name>` with screenshots, logcat and reports.

Signed store builds are made only by `release.yml` from the repository secrets.
